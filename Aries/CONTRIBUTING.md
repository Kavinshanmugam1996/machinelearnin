# Contributing to AIRES™

Thank you for your interest in contributing to AIRES™! To maintain a professional and scalable codebase, we follow these enterprise-grade standards.

## Branching Strategy

We follow a simplified GitFlow model:

- **main**: Production-ready code. No direct pushes allowed.
- **develop**: Integration branch for new features.
- **feature/*** : Individual features (e.g., `feature/custom-risk-scoring`).
- **bugfix/*** : Bug fixes (e.g., `bugfix/pdf-generation-error`).
- **hotfix/*** : Emergency production fixes.

## Pull Request Process

1. Create a feature or bugfix branch from `develop`.
2. Push your changes and open a Pull Request (PR) against `develop`.
3. Ensure all CI checks pass.
4. Request a review from at least one maintainer.
5. Merge after approval.

## Code Standards

- Follow PEP 8 for Python code.
- Ensure all new features are documented in `docs/`.
- Include unit tests where applicable.
